# session-context

The `session-context` server plugin exposes a `session_context` tool that loads another session's full active post-compaction context as a filtered transcript. Set `previousCompaction: true` to select the active window immediately before the latest completed compaction. That window starts with the preceding completed checkpoint, if any, and ends before the latest one. Failed and running compactions do not define boundaries. A session with no completed compaction returns `NO PREVIOUS WINDOW`.

The tool description warns models that the result can be very large and directs them to call it only when explicitly instructed by the user or a dispatching parent's brief. Pass the `MARKER` from a prior response as `sinceMarker` to read incrementally within the selected window; when `MORE: true`, repeat with that marker. A marker missing from the selected window produces a notice and a fresh read of that window, not a switch to the current one.

The plugin uses OpenCode V2 `session.context` for the default window and the paginated message API for historical windows. It discovers the running local service without starting another one and checks that the discovered server PID matches its own process before reading historical messages. An undiscoverable server or a different process returns an error; standalone and explicitly hosted servers without a matching local registration cannot use historical reads. The tool does not modify the target session. Transcript rendering omits reasoning, system/control messages, and skill bodies; tool and shell output are truncated. Completed checkpoints include the summary and OpenCode's retained recent conversation text, which is already serialized by OpenCode and may carry content that its typed-message transcript renderer would otherwise omit (such as reasoning or skill text). Treat the transcript as filtered recovery context, not a lossless record.
