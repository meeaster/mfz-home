# roles

## Intent

Role definitions for Cairn: each role is a job with a purpose, boundaries, an expected result, skills, and a model. Any session uses them two ways: delegated, briefed to a `general` subagent on the role's model, or assumed, when the human asks the session to act as the role and works with it directly. `orchestrate` builds on this skill as the lead's playbook.

Not for: entering orchestration, choosing models (that is `orchestration-routing`, selected per profile), or the delivery flow.

It serves the goals in Cairn's `VISION.md`: cost control through a model per job, trusted delivery through separate jobs checking separate things, and the principles that every handoff loses intent and that skills are chosen, not matched.

Success: a delegated subagent gets a brief that names its role's expectations, model, and skills, and needs no rework for missing context. An assumed role announces what changes, loads its own skills, and still delegates what another role does better. Taste skills load only where a role or task type lists them.

## Scenarios

- **Delegate one task from an ordinary session**: the human asks for a piece of work to go to a subagent; the session picks the role, model, and skills and briefs it, without entering orchestration or running the delivery flow.
- **Act as the creative director**: the human asks the session to take the role; it states what it does itself, loads the medium's tool skills, names the role's bound model when the session's differs, holds the conversation as a design partner, and can still send an implementer off.
- **Return to the lead**: from an assumed role, the human asks to orchestrate again; the session loads `orchestrate`.
- **Storyboard then build**: a creative director draws boards in OpenPencil alone, exports them at full size, and lists them by frame name; an `implementer/motion` builds from them without redesigning.
- **Verify with gaps**: the inspector records evidence and gaps directly in its Cairn-assigned per-session folder while leaving the observed target and repository unchanged. Knowledge promotion is a separate human-authorized curation assignment, not a writer relay in verification.

Wrong behavior to rule out:

- **Taste skill by description**: three animated-slide designs each loaded `impeccable` and `diagram-design` because their descriptions matched, which may have narrowed the designs.
- **Lead behavior after a switch**: an assumed creative director keeps delegating its own design work because the lead's delegate-by-default instructions are still in context.
- **Re-reading the roles each dispatch**: the lead reloads `roles` or reads its file before every dispatch instead of using it from context.
- **Parallel storyboards**: two designers in one OpenPencil app; the second couldn't export because only the active tab exports, and the server's session limit filled up.

## Decisions

- **Split from `orchestrate` so any session can use roles** (human, 2026-10-13). See `orchestrate`'s record. This skill is model-invocable, unlike `orchestrate`, because an ordinary session must reach it when the human asks to delegate or to act as a role.
- **Roles can be assumed** (human, 2026-10-13). Working with a creative director through a subagent puts the lead between the human and the director, and both relays lose intent; assuming the role removes them and keeps the session's context. Only conversational roles are assumable. The lead is assumed by loading `orchestrate`, so the lead has one definition. The model doesn't follow an assumed role, so the switch names the bound model and the human decides.
- **Skills are chosen per role and task type** (human, 2026-10-13). Subagents load what the brief names, plus tool skills for tools the work uses. Taste skills (`impeccable`, `diagram-design`, `dataviz`, `technical-writing`, `unslop`) load only where a role or task type lists them, because they make style decisions that belong to the human or a creative role. The categories live here, not in the configuration catalog (human): Cairn owns the workflow, and the catalog is configuration management.
- **Creative director with `spec` and `storyboard` task types** (human, 2026-10-13). A test on one 15-second fframes scene found that the designer model sets the quality and the builder barely matters: every builder reproduced its design closely, from a text spec or from OpenPencil storyboards. Opus storyboards cost $2.32 against $1.75 for an Opus text spec, for about the same build quality, and Sonnet storyboards ($1.20) were nearly as good as Opus's. What storyboards add is a design the human can see, comment on, and change before anything is built, so the human picks the form. The OpenPencil rules in the storyboard task type (work alone, full-size exports, frame names) each come from a failure in that test.
- **`implementer/motion` builds creative packages** (2026-10-13). In the same test, builders that read positions from the OpenPencil document matched their boards more closely than builders that had only the board images.
- **Bindings: Astra directs, Luna High builds motion, an inspector checks** (human, 2026-10-13). The Personal profile reaches only OpenAI models in OpenCode, so the creative director runs on Astra rather than the Claude models tested. Luna High built storyboards for about a tenth of Haiku's cost ($0.07–0.13 against $1.26–1.34) with the right layout and motion, but rendered bold weights as regular, left a stray label, and never compared its frames with the boards, though its brief said to; so a motion build is followed by an inspector that does the comparison. Luna Max spent ten minutes reasoning before writing code and was stopped. The fonts rule for the creative director came from a test run that proposed fonts the fframes project didn't have. Astra's design quality is untested.
- **OpenCode only** (2026-10-13). Dispatch relies on OpenCode's `general` subagent and model references from `orchestration-routing`; in Claude Code the model-invocable description would fire in ordinary sessions without a usable routing table. `orchestrate` is still selectable in Claude Code, where it now can't load `roles`; that is accepted while orchestration is tested only in OpenCode.
- **Deferred roles**: ui-ux-designer, session-analyst, and agent-author are deferred; scribe is experimental, because Cairn saves results and the conversation export already records the session.
- **Every role runs on `general`, with boundaries stated in the brief** (human, 2026-10-07). Current models respect "read-only" in a prompt, so named agents with their own permissions weren't worth maintaining. A plugin hook that injected role instructions was proposed and rejected (human, 2026-10-09): the subagent shouldn't have to work out its job; the brief gives it.
- **Name skills to load; don't point at their files** (human, 2026-10-09). A brief says "load the `pr-review` skill", not "read this file".
- **Model bindings live in a separate, profile-selected `orchestration-routing` skill.** Personal and Work share this workflow but bind different models and gateway aliases, so the roles and briefing stay shared and each home owns its models. The initial bindings reused the old agents' models (human, 2026-10-09); tiers were deferred.
- **Confirm a model once per session, not per dispatch.** In trial runs the lead spent two steps on model lookups before every round of dispatches.
- **Guidance work gets its own models and review** (human, 2026-10-12). Writing skills and agent instructions is different from coding, so `implementer/instructions` has its own routing row instead of falling back to the implementer default, and `reviewer/instructions` exists because `reviewer/code` loads a code-quality review that doesn't fit guidance.
- **Verification is a skill the brief names** (human, 2026-10-12). Implementers and inspectors load `verification`; the skill holds how, this one says who and when. QA loads the project's own verification skill only to navigate, since a pass/fail checklist would narrow its judgment, and accepted QA findings become criteria.
- **Inspectors own session verification records** (human). The human wants the inspector that finds a gap to record it directly, rather than passing it through a writer. Session evidence is the narrow writing responsibility within an otherwise read-only role. The knowledge base is curated and maintained, so session findings stay in the Cairn-assigned per-session folder until a separate, explicitly authorized review, refactor, or curation task promotes them.
- **Inspector, QA, and reviewer are separate** (human, 2026-10-09). Checking acceptance criteria is cheap, so an inspector always runs in the background after any change a user can exercise; before 2026-10-12 this covered UI work only. Judging whether an interface looks right needs a stronger model, so QA runs only on request. Code review is a third job, split out after a reviewer conflated it with QA.
- **Triage is cheap and dispatched without asking; escalation needs agreement** (2026-10-12). Default triage costs about a cent on `gpt-6-luna#max` and must be told to load `debugging`, because cheap models rarely load it from its description. The repository's debugging-skill evaluation is the evidence. This replaced triage on Sol behind an explicit request.
- **Reuse is judged against the original assignment, not cache warmth.** This replaced a hard 150,000-token cutoff, which now serves only as a warning.
- **Agent-facing records: audience, attribution, portability, and a source check** (human, 2026-10-12). Two writers persisted presentation research as Markdown in a Git repository for agents and the human to continue design work. Independent reviews found both compressed and paraphrased, because the brief said "concise" and never said agents would read it; attributed the lead's proposals and inferences to the human and invented reasons the human never gave; and used absolute machine-local paths in repository files. Nothing checked the record against its sources. So a writer's brief names its readers, the writer labels what the human stated apart from accepted and unanswered lead proposals, records cite only sources their readers can open, and the lead decides whether such a record is worth a cheap source check. Citing the source session message for each statement was tried and dropped (human, 2026-10-12): in the retest, writers cited message numbers in a session that exists only on the human's machine, once mistaking a file line number for one, and nobody else loading the repository could follow them. Because later readers can't check those sources, accuracy has to be established before the record is accepted; the check is still a judgment, not automatic every time. Plain repository context files go through the writer role, not `effort-context`, which serves Cairn efforts and records (human).
