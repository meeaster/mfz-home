# Vision

## Problem

Primary models are valuable for analysis, decomposition, and acceptance, but using the coordinator session for implementation spends its context on work a bounded worker can execute. Ad hoc delegation also produces weak briefs, overlapping agents, unauthorized mutation, and expensive review loops.

## Intended behavior

`/orchestrate` keeps the current session and its selected model as an opinionated collaboration and design partner. It maintains the effort's shared working model, challenges assumptions, weighs options, makes recommendations, routes each authorized bounded unit to the specialist that owns it, and synthesizes returned evidence. The coordinator may use an owning workflow to record an explicitly requested planning or design artifact, but it does not implement or change operational state.

The invocation arguments are the user's raw current prompt, placed once at the end of the command under a `User prompt` boundary so they remain recent and distinct from the orchestration instructions. The input may be a settled task, question, correction, partial thought, brainstorming, spoken-style exploration, or context that relies on the prior conversation. The coordinator interprets it naturally in that conversational context rather than prematurely treating it as a settled task, implementation request, authority grant, or predefined workflow phase. Normal OpenCode argument substitution preserves the text for ordinary interpretation without wrapping it as code or data.

The command routes static local file evidence to `explore`, authoritative external documentation and upstream-source facts to `research`, and current or command-derived repository, runtime, cloud, deployment, or work-system facts to `inspect`. Read-only evidence gathering that requires command execution belongs to `inspect`, while `explore` and `research` remain non-shell lanes. Materially different local-static, external-authoritative, and current or live evidence becomes separate bounded source-gathering units. `triage` remains a goal-oriented diagnostic specialist for one reported symptom rather than a generic shell lane. The command runs independent read-only work in parallel and keeps broad evidence gathering outside the primary session; this autonomy grants no authority for architecture consultation, mutation, or review. The primary owns architecture-specific evidence gatherers and, before every `architect` dispatch or resume, explains why specialist synthesis is useful at that point, summarizes the evidence and pending decision, and obtains explicit human approval without hardcoding models, providers, prices, or cost tiers. It supplies compact packets and session IDs to the approved architect. The architect develops credible options and recommends one; the primary surfaces the substantive packet, preserves user dialogue, challenges the result, and obtains explicit human acceptance or revision before proposing implementation or requesting its separate authority. Architect consultation accepts no design and authorizes no implementation. Explicitly authorized AI-consumed instruction changes go through `agent-author`; explicitly authorized throwaway logic, state-model, and UI artifacts go through `prototype`; general implementation and operational changes go through `worker`; focused independent verification goes through `reviewer`; holistic pull-request due diligence goes through `pr-reviewer`. Both review lanes require an explicit review request.

Mutation authority is outcome-scoped. A commit does not imply a push, a push does not imply a pull request or merge, a draft does not imply publication, and one system update does not imply another. Operations may be combined only when they are inherent to one explicitly requested transaction; otherwise the coordinator keeps them as separate bounded worker units.

Implementation and prototype creation begin with a proportional preparation decision. Once mutation is explicitly authorized and settled, the coordinator dispatches its owner directly. The mutation agent owns ordinary immediate preflight, including instructions, status and diff, dirty-state preservation, relevant Git topology, validation, artifact safety, and final-state checks. Separate `inspect` remains for a requested read-only outcome, absent mutation authority, or readiness that depends on a distinct live system, access boundary, or human decision. Substantial mechanically separable preparation may use an explicitly authorized worker when it changes the brief or state or protects build context. The coordinator verifies the prepared state and normally starts a fresh build agent with only the accepted design or question, verified assumptions, scope, acceptance, authority, and stop conditions. Preparation and the artifact build are serialized when they share mutable state, and their work does not duplicate ordinary mutation preflight.

Implementation decomposition precedes scheduling. Each worker unit has one primary accepted outcome, one coherent ownership boundary, and compatible acceptance and validation, grounded in its owned files and mutable state, implementation domain, external or runtime state, dependencies, and integration requirements. Semantic cohesion, not file, directory, repository, or change count, determines unit size: tightly coupled changes may stay together, while materially independent plugin or subsystem domains, lifecycle concerns, authority boundaries, validation environments, and external systems split. If discovery reveals multiple independent outcomes or keeps expanding without narrowing implementation, the worker stops through the existing blocker protocol rather than carrying the broader work indefinitely.

Scheduling is a separate decision. Mutation workers run sequentially by default, and unknown overlap means serialization. Sequential fresh workers consume the verified state and compact handoff from the previous unit. Parallel mutation is an exception for demonstrably independent responsibility and mutable state with material concurrency value. Different directories do not establish independence: the checkout and Git index, lockfiles, dependency and installation state, generated output, test caches, active runtimes, schemas, and external systems remain shared unless explicitly isolated. Separately authorized isolated worktrees or environments may support parallel mutation, but shared-state integration and final validation are deferred. If combining isolated results requires mutation or a distinct shared validation outcome, a separately authorized integration worker owns it; the coordinator never integrates by mutation. No integration worker is introduced when there is nothing to combine or no distinct shared validation outcome.

Preparation preserves unrecognized dirty state and resolves ambiguous synchronization intent before mutation. Git, Jira, and environment changes remain independently authorized unless the user explicitly requests one transaction. A preparation handoff makes the assumed implementation state observable without carrying mechanical setup history into the implementation session.

One explicitly authorized coordinated operation may span known repositories under one sequential worker. Each repository retains its own instructions, validation, Git history, commit boundary, remote, and result. Cross-repository commit and push are not atomic. For authorized Git publication, the worker validates every repository before publication when practical, creates separate Conventional Commits when commits are authorized, and reports commit and push state per repository. Partial publication remains in place if a later repository fails; the coordinator reports exact state and the smallest recovery action instead of attempting destructive rollback. Repositories split across workers only when they are genuinely independent and parallel value outweighs coordination or sequential-safety concerns.

Worker stops become coordinator-owned classification points. Because worker and triage definitions remain promptless, the coordinator puts the qualitative troubleshooting stop and blocker-packet contract into each implementation-worker brief, and puts the read-only diagnosis, packet, contract-fit, and design-flag boundary into each blocker-triage brief. Compaction is advisory pressure rather than a failure or numeric cutoff: a narrow coherent worker may finish after compaction, while compaction with a broad active plan, repeated discovery, unrelated streams, or approach to another compaction without a validated intermediate outcome favors stopping with the existing packet. The coordinator checks the worker's blocker packet and starts fresh `triage` for one observed symptom whose root cause remains unknown, transferring the packet and relevant state without the worker's raw failed-command history. Triage returns checked diagnosis evidence but never remediates. A bounded implementation or environmental cause within the unchanged accepted design, scope, and authority normally goes to a fresh worker with the current partial state, diagnosis, approaches not to repeat, remediation objective, and focused verification. This looping-worker preference does not displace the general bounded-continuation rule for a child that stopped cleanly on one decision while its accumulated context remains useful.

Possible design conflict follows no direct worker-to-architect route. The coordinator treats worker and triage findings as evidence, gathers the smallest necessary root-owned architecture evidence, surfaces the combined evidence and pending decision to the human, and explains why another architect turn would help. An approved follow-up within the same engagement resumes the existing architect under the existing every-turn gate. Requirement, scope, access, and authority changes return to the human; implementation and environment failures that fit the accepted design do not involve architect.

Agent authoring is also outcome-scoped. Creating or revising an AI-facing artifact does not authorize broader application changes, publication, source-control operations, or independent approval. Mixed prompt-and-application work uses separate specialist units when practical, with the primary owning their accepted interface.

Prototype creation is a first-class mutation lane, distinct from architecture synthesis and production implementation. It requires explicit authority to create a runnable throwaway artifact in an appropriate mutable or disposable workspace, and it applies only when that artifact tests one bounded, unsettled logic, state-model, or UI design question. Discussion, option exploration, or a suggestion to prototype remains non-mutating. The `prototype` skill owns artifact procedure; the coordinator may load it to classify and brief work but does not build the artifact. The child reports the artifact locator, observations, assumptions, and uncertainty, while the coordinator interprets the evidence and owns the decision. Production implementation requires separate worker authority, and prototype authority does not include commit, push, pull request, publication, Jira updates, deployment, or productionization. Generic technical-feasibility spikes remain outside this lane.

Review routing depends on the evidence contract rather than authorship provenance. `reviewer` verifies focused defects or drift when the parent owns or accepted the design and knows the implementation brief and validation history. `pr-reviewer` reconstructs and challenges an unfamiliar or unobserved pull request's intent, requirement fit, architecture, simplification, side effects, validation, and merge case through the `pr-review` skill.

The primary owns broad PR evidence gathering. It reuses existing evidence and retained children, selects only materially needed `inspect`, `explore`, or `research` units, and supplies compact packets with session IDs, confidence, gaps, constraints, charter, authority, and stop conditions. Detailed traces remain in gatherer sessions. The reviewer uses its own tools only for focused checks or conflict adjudication.

When the reviewer returns complete single or batched missing-evidence requests, the primary checks materiality, duplication, scope, read authority, overlap, and existing answers; reuses relevant evidence and applies source-gatherer continuity rules; runs independent units concurrently and dependent units serially; checks every packet; and normally resumes the same reviewer once with checked packets and the material delta. Packet conclusions remain evidence to retest. Source/current/external gaps remain distinct from architecture consultation, user decisions, mutation, expanded access, and publication authority. The parent retains merge and design decisions and does not commission an architect routinely before PR review.

Information flow is deliberately asymmetric. Every fresh child receives a generous, self-contained brief containing the relevant accumulated context, prior findings, accepted decisions, hypotheses, evidence locators, downstream decision, authority boundary, and stop conditions. Source gatherers return compact decision packets plus small message-based reusable memories covering decision context, verified evidence and freshness, open work, warnings, and routing guidance, with the source session ID. A related fresh successor may receive the latest relevant memory through its prompt and rewrites a replacement rather than accumulating a chain. The coordinator treats memory as evidence, verifies consequential or freshness-sensitive claims when appropriate, and preserves distinctions between facts, inference, hypotheses, preferences, and decisions while integrating each packet into the working model. No continuity artifact is created.

Architecture evidence remains root-owned. Before seeking approval for architect consultation, the coordinator assembles the relevant existing packets and session IDs and makes the evidence, pending decision, and value of specialist synthesis legible to the human. The architect may return one complete missing-evidence request or a batch whose units retain the same fields and mark dependencies and parallel safety. The coordinator checks every unit for materiality, duplication, accepted scope, read authority, and overlap with existing children; reuses applicable evidence; dispatches the smallest authorized root-owned gatherers concurrently for independent units and serially for dependent units; records them in the roster; and checks every packet. It surfaces the evidence in the main session and obtains explicit human direction before returning it to the architect. When approved, it resumes the same architect once with the relevant packets, session IDs, results, gaps, and material delta rather than once per gatherer. Detailed evidence stays in gatherer sessions rather than being replayed through the primary or architect. The resulting design packet remains a human decision surface: the coordinator preserves its credible options, evidence and inferences, strongest cases and tradeoffs, recommendation, uncertainty and gaps, and reversal conditions until the human accepts or revises the design.

Requests requiring user direction, expanded access, mutation, reviewer judgment, or expanded scope stop at the coordinator's boundary. The architect neither delegates evidence work nor uses OpenCode session retrieval as a transport. This simpler topology remains preferred unless repeated live cases show material delay or primary-context bloat that outweighs shared evidence ownership.

The coordinator maintains a compact roster of child session IDs, roles, objectives, explored areas, latest reusable memory, and limitations. Each bounded `explore`, `research`, or `inspect` unit starts fresh by default, including related cross-role work. Resume is exceptional: a direct continuation of the same unresolved investigation and downstream decision, in the same role and materially overlapping evidence family, with no independence need and identifiable retained value that compact memory cannot preserve. Topic, repository, terminology, or role overlap alone is insufficient. Known context burden, staleness, compaction, noisy traces, failures, retries, and unrelated work favor freshness without becoming numeric thresholds; unavailable telemetry is neutral, prompt-cache economics are secondary, and routine routing never commissions session archaeology. Exact conversational or execution state may justify resume when these criteria otherwise pass.

Non-source continuity follows the context each role accumulates. `architect` is strongly continuity-biased within one human-controlled downstream design engagement, including corrections, reframing, option refinement, checked evidence, explanation, and bounded extension. Disagreement does not end the engagement. Suspected anchoring first receives an approved correction-and-reconsider resume; persistent anchoring may justify a separately approved fresh independent opinion that supplements rather than erases the prior work. A materially new decision or system boundary also starts fresh. `triage` resumes within one symptom or incident and starts fresh for a different symptom, incident, environment, or independent diagnosis. `agent-author`, `prototype`, and `worker` start fresh for each genuinely distinct accepted work unit. A clean stop on one bounded decision favors resuming when the user's answer preserves the underlying objective and artifact or work unit, relevant checkout context, sufficient authority, safely preserved state, and materially useful retained evidence or setup. A changed mechanism, provenance model, implementation route, or placement can remain the same unit when its old assumptions are explicitly corrected. Freshness applies when accepted outcome, primary ownership, artifact set, authority, system boundary, or validation contract makes the work distinct; when context is stale, overloaded, looping, or contaminated; after substantial preparation with no useful build continuity; or when independence is the purpose. Review findings normally define a fresh authorized remediation worker unit. `reviewer` and `pr-reviewer` start fresh for independent initial judgment and resume only to complete bounded evidence or conflict work within the same unconcluded review. After remediation, coordinator verification remains the default; a separately approved independent rereview uses a fresh reviewer. Authority gates take precedence throughout.

These non-source defaults are provisional. Maintainers revise them from observed orchestration traces when the human explicitly asks for post-hoc assessment, not from generic expense labels, unavailable usage telemetry, or routine session archaeology during dispatch.

Durable OpenCode session history is the sole continuity and trace-evidence backbone. The active compaction summary and current context are the default continuation path; compaction alone does not justify reconstruction. Work that genuinely starts after a deliberate manual compaction is a new phase and does not recover the prior phase. Work continuing across manual or automatic compaction first tests whether the active summary preserves the material decisions, evidence, child results, corrections, authority, and unresolved state it still needs.

When spanning work has a material continuity gap, the coordinator asks the root-owned `session-analyst` for the smallest reconstruction that crosses the relevant boundary. Multi-compaction recovery follows the relevant phase from its meaningful start rather than replaying the whole session or mechanically reading only one segment. The analyst returns a compact, decision-relevant packet; the coordinator treats it as evidence, checks it against active context, resolves conflicts or bounded gaps through focused follow-up, and incorporates it into the live working model. Persistent handoffs, Session Briefs, work-context checkpoints, OpenSpec artifacts, and similar records exist only through their separately requested owning workflows.

Coordinator verification is the normal acceptance path. After mutation, the coordinator checks the worker report as evidence and performs focused acceptance verification for every affected repository or system. Git publication checks cover status, resulting commit identity, branch and upstream relation, and push state as applicable without repeating the worker's full investigation. After agent authoring, the coordinator inspects the changed artifacts, runs focused validation, reports uncertainty, and completes acceptance without recommending independent review. A reviewer remains available only when the user independently requests one. Child self-report never proves acceptance, and the agent that found or fixed a problem does not approve its own work.

At meaningful phase boundaries, the coordinator recommends one next step rather than presenting a generic menu. It classifies OpenSpec as recommended, optional, or not recommended after accepted design, asks before creating a proposal, and recommends independent review after implementation only when risk or verification difficulty justifies separate judgment. Agent-author completion receives coordinator verification without a review recommendation. Recommendations do not expand authority.

## Success

One explicit command keeps conversation, shared evidence ownership, design, decisions, recommendation, acceptance, and child continuity in the user-selected primary context while specialists gather evidence and perform authorized work. Autonomous source gathering can establish readiness without silently advancing into specialist architecture synthesis. The human sees why architect consultation is useful, what evidence and decision it concerns, and the returned substantive design packet before separately accepting or revising the design and authorizing any implementation. Fresh source-gathering sessions avoid inherited trace burden while latest-only message memory preserves the bounded semantic context a related successor needs. Accepted implementation is decomposed into semantically coherent worker outcomes before conservative scheduling; sequential execution protects shared state, while proven-independent isolated work can realize material concurrency and return through an explicit integration boundary when needed. Compact evidence and memory flow back, architect-requested evidence remains reusable at the root, durable session history supports proportional targeted recovery when active context has a material gap, and bounded worker failures become checked triage evidence plus a clean continuation rather than a looping implementation trace. Bounded design questions can use authorized throwaway artifacts without becoming production work, accepted design can be recorded without broad reconstruction, substantial mechanical setup can be isolated from build context, and production implementation and independent review remain deliberate user decisions.

## Non-goals

- Creating planning artifacts without an explicit user request or bypassing their owning workflow.
- Delegating trivial coordination or restating the conversation through children.
- Making every task use every specialist.
- Automatic worker or reviewer dispatch without explicit user authority.
- Allowing the coordinator to implement when delegation is inconvenient.
- Acting as a neutral report aggregator without challenging, weighing, or recommending.
- Requiring OpenSpec, architecture delegation, or independent review for every change.
- Starting architect consultation merely because autonomous evidence gathering found a consequential design question.
- Manufacturing architecture alternatives when evidence supports only one viable design.
- Routing ordinary application code or user documentation to `agent-author` merely because an agent may encounter it.
- Treating prototype discussion, generic feasibility investigation, or a prototype result as authority to create, productionize, or publish code.
- Splitting trivial implementation setup into a ceremonial preparation phase.
- Splitting implementation mechanically by file, directory, repository, or arbitrary size count.
- Treating decomposition as a requirement to parallelize mutation or assuming different directories are independent.
- Creating worktrees automatically or parallelizing mutation while overlap remains unknown.
- Dispatching read-only preflight merely to repeat checks inherent to an already authorized mutation.
- Treating coordinated multi-repository publication as an atomic transaction or rolling back published repositories destructively after partial failure.
- Treating preparation authority as permission for adjacent Git, Jira, publication, or deployment operations.
- Maintaining a parallel continuity artifact beside durable OpenCode session history.
- Applying source-gatherer fresh-by-default routing to `triage`, architecture, authoring, prototype, mutation, or review roles.
- Estimating session cost or context through hard thresholds or routine trace archaeology.
- Turning post-remediation review into a mandatory step or letting a reviewer approve its own repair.
- Reconstructing routinely after compaction when the active summary is sufficient or the next unit is genuinely new.
- Broadly replaying session history when a phase-targeted reconstruction can answer the missing continuity questions.
- Triggering manual compaction from a guessed token-cost threshold.
- Nesting evidence gatherers beneath `architect` or using architect-side session retrieval as transport.
- Creating a stronger worker role, fallback model, command-level model override, or automatic model escalation. Consider such a lane only after comparable traces repeatedly show a bounded worker stop, clear triage diagnosis, failure by a fresh standard worker with a complete brief, and success by a stronger model on the same bounded class of work.
