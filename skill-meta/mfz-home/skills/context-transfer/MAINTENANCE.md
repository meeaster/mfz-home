# Maintenance

## Dependencies

The runtime skill has no required scripts, tools, repositories, artifact hosts,
or provider-specific behavior. Its references disclose human-consumer shaping
and artifact-workflow behavior only when those branches apply. Artifact-specific
skills and destination instructions may depend on it while retaining their own
format, authority, validation, and publication contracts.

## Change Procedure

1. Read every package artifact before changing behavior.
2. Classify the issue as invocation, transfer-contract inference, context
   selection, parent-to-agent task framing, specialist-artifact preservation,
   consumer shaping, reference proportionality, or cold-consumer
   validation.
3. Inspect every declared dependent skill before changing shared semantics or
   reference routing.
4. Make the smallest behavioral change and update affected evaluations.
5. Verify positive and adjacent-negative invocation cases when the description
   changes.
6. Record consequential decisions or reversals in `LOG.md`.

## Portability Review

Verify that runtime instructions contain no personal names, private repository
assumptions, fixed workspace layout, artifact-host template, publication command,
or claim that one portability level is universally correct.

## Verification

Static review must confirm valid front matter, coherent package artifacts,
conditional reference routing, and clear ownership boundaries with dependent
skills. Representative execution should inspect the produced artifact and test
it from the declared destination, not rely on the authoring agent's summary.
