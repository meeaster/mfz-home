# Maintenance

## Dependencies

The runtime skill has no required scripts, references, tools, knowledge repositories, or provider-specific behavior. Applicable repository instructions and available authoritative evidence supply its inputs.

## Change Procedure

1. Read every package artifact before changing behavior.
2. Identify whether the issue concerns invocation, evidence authority, document shaping, reconciliation, or handoff.
3. Make the smallest behavioral change and update affected evaluations.
4. Verify positive, negative, and adjacent invocation cases when the description changes.
5. Record consequential decisions or reversals in `LOG.md`.

## Portability Review

Verify that runtime instructions contain no personal paths, private-source assumptions, fixed workspace layout, harness commands, or mandatory document template. Environment-specific installation and enablement remain outside the package.

## Verification

Static review must confirm valid skill frontmatter, coherent package artifacts, and no broken path assumptions. Representative execution should inspect the resulting vision and related diffs rather than rely on the agent's summary.
